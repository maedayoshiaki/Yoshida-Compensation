# ISO400 HDR色補償・全再校正レポート

実施日: 2026-07-30  
ブランチ: `feature/triggered-batch-capture`

## 1. 実施内容

撮影設定の基準値は変更せず、次の測光処理をHDRで最初から実行した。

- チャンネルランプ投影によるRGB別逆LUT計測
- 17段階グレー投影によるRGB別逆LUT計測
- ガンマなし、解析逆ガンマ、チャンネル逆LUT、グレー逆LUTの4方式それぞれの64色・4段階色変換行列
- nature 3画像の5条件投影結果
- car、car-newを直接入力した5条件投影結果
- 0、85、170、255の4段階グレー。255が白投影

GrayCodeだけはHDR化していない。2026-07-30に再計測済みの
`data/graycode_recalibration_20260730/p2c_dense_active_1920x1080.npy`
をそのまま使用した。

## 3. HDR合成の実装

1. 全パターンを基準Tv 1/15秒でトリガ撮影する。
2. 基準露光の確認ROIが暗いパターンだけ1/4秒、必要なら0.5秒で追加撮影する。
3. 飽和したパターンだけ1/30秒、必要なら1/60秒で追加撮影する。
4. 実際に選択されたTvの露光時間比で、追加露光を1/15秒相当の値へ戻す。
5. 暗部は飽和していない最長露光、飽和部は短露光で、画素・RGBチャンネルごとに置換する。
6. HDR値は1を超えて保持し、色行列fit前にはclipしない。

追加ブラケットは必要な投影だけに限定した。追加RAWは1枚ずつ現像・合成して
破棄するため、露光段数分のフル解像度配列を同時に保持しない。

## 4. HDR逆LUT

### チャンネルランプ

- 保存先: `data/hdr_recalibration_20260730_iso400/inverse_lut_channel/inverse_lut.npz`
- 基準露光: 49枚
- 追加露光: 32枚
- 合計: 81枚
- LUT終端 R/G/B: `0.875855 / 0.875855 / 0.688172`

この実写では、修正前コードによる基準Tvと同値の冗長な「長露光」9枚が入った。
露光比1なのでLUT値には影響しないが、撮影時間は浪費した。現在のコードでは
同じTvを二重撮影しない。

### グレー投影

- 保存先: `data/hdr_recalibration_20260730_iso400/inverse_lut_gray/inverse_lut_gray.npz`
- 基準露光: 17枚
- 追加露光: 13枚
- 合計: 30枚
- LUT終端 R/G/B: `0.750733 / 0.875855 / 0.688172`

どちらもRGB別1D LUTであり、3D LUTではない。グレー投影方式も、同じ撮影から
RGB各チャンネルを別々にfitしている。

## 6. nature画像のHDR投影結果

nature_1、nature_2、nature_3は通常のsRGB画像として正確なsRGB EOTFで
線形化してから補償した。15条件画像のHDR撮影は、基準15枚、長露光27枚、
短露光8枚の合計50枚、撮影・現像249.22秒だった。

3画像平均:

| 条件 | PSNR [dB] | SSIM | Delta E76 |
| --- | ---: | ---: | ---: |
| 補償なし | 19.73 | **0.8316** | 24.23 |
| 補償あり・ガンマなし | 18.26 | 0.7112 | 24.76 |
| 補償あり・解析逆ガンマ | 19.29 | 0.7446 | 24.52 |
| 補償あり・チャンネル逆LUT | **22.51** | 0.8072 | **14.91** |
| 補償あり・グレー逆LUT | 21.09 | 0.7449 | 17.20 |

補償方式の中ではチャンネル逆LUTが3指標すべてで最良だった。全条件の
SSIMだけは補償なしが最高である。

単一露光ISO400版との差（HDR − 単一露光）:

| 条件 | PSNR | SSIM | Delta E76 |
| --- | ---: | ---: | ---: |
| 補償なし | -0.30 | -0.0110 | +0.64 |
| ガンマなし | -1.71 | -0.0341 | +8.84 |
| 解析逆ガンマ | -3.65 | -0.0471 | +10.76 |
| チャンネル逆LUT | -0.78 | -0.0144 | +0.43 |
| グレー逆LUT | +0.09 | -0.0220 | -0.64 |

HDRは白飛びした放射応答を復元できたが、色補償指標を一律には改善しなかった。
現在の色補償モデルは画素別4 x 3アフィン変換なので、HDRで得た非線形かつ
広ダイナミックレンジの応答を十分表現できない可能性がある。ただし、この実験
だけで悪化原因を一意に断定はできない。

## 7. car、car-newの直接入力

指定どおり、carとcar-newにはsRGB逆ガンマを掛けず、8bitコード値を0～1へ
正規化してそのまま補償目標へ入力した。合計10条件画像のHDR撮影は31枚、
152.06秒だった。

| 画像 | 条件 | PSNR [dB] | SSIM | Delta E76 |
| --- | --- | ---: | ---: | ---: |
| car-new | 補償なし | **21.71** | **0.7227** | **15.54** |
| car-new | ガンマなし | 15.83 | 0.6024 | 20.96 |
| car-new | 解析逆ガンマ | 11.64 | 0.5273 | 28.71 |
| car-new | チャンネル逆LUT | 12.73 | 0.5299 | 25.74 |
| car-new | グレー逆LUT | 12.42 | 0.5273 | 26.70 |
| car | 補償なし | **17.45** | **0.7722** | 32.30 |
| car | ガンマなし | 15.77 | 0.6807 | 21.16 |
| car | 解析逆ガンマ | 12.73 | 0.6591 | 22.73 |
| car | チャンネル逆LUT | 13.86 | 0.6254 | **20.80** |
| car | グレー逆LUT | 13.11 | 0.6187 | 21.88 |

car-newはすでにガンマをキャンセルした暗い画像である。それを「線形値」として
直接入力し、撮影結果を再びsRGB表示用に符号化して元の暗い8bit画像と比較する
ため、補償後が明るく見える。この直接入力条件ではcar-newの補償なしが全指標で
最良になった。carでは補償方式中のDelta E76最小がチャンネル逆LUTだった。

## 8. 4段階グレー・白投影

4パターンのHDR撮影は、基準4枚、追加5枚、合計9枚、44.46秒だった。

| 投影コード | 確認ROI平均線形値 |
| ---: | ---: |
| 0 | 0.001254 |
| 85 | 0.131785 |
| 170 | 0.746889 |
| 255 | 1.601412 |

4点は厳密に単調増加した。白255のROI平均RGBは
`1.80597 / 1.11052 / 1.88768`、最大値は約2.53まで得られた。
これは単一露光の0～1 clipより上の情報をHDRで回収できたことを示す。
目視用PNGとコンタクトシートは表示のため1へclipしており、行列fitに使った
HDR float値そのものではない。

## 9. 所要時間

方式別64色校正について、撮影・現像とfitを合計した比較:

| 方式 | 単一露光 | HDR | 倍率 |
| --- | ---: | ---: | ---: |
| ガンマなし | 268.42秒 | 898.30秒 | 3.35倍 |
| 解析逆ガンマ | 266.34秒 | 935.69秒 | 3.51倍 |
| チャンネル逆LUT | 268.08秒 | 762.89秒 | 2.85倍 |
| グレー逆LUT | 264.43秒 | 738.72秒 | 2.79倍 |

最終nature比較は単一露光63.30秒からHDR249.22秒へ3.94倍、
car/car-new直接比較は46.19秒から152.06秒へ3.29倍となった。
HDRは必要パターンだけ追加撮影しているが、フル解像度RAWの撮影・転送・現像が
支配的なため、今回は高速化ではなくダイナミックレンジ確保との交換になった。

## 10. 目視確認と既知事項

- nature、car、car-new、4段階グレーの比較シートを目視確認した。
- チャンネル逆LUTのnature結果が5条件中で最も目標色へ近く見えた。
- 以前から見えていた固定矩形はHDRでも同じ位置に残った。前フレーム混入ではなく、
  投影面または撮影系に固定された特徴と考えられる。
- HDR合成値を保存したPNGは表示用sRGBへclipされる。数値確認はJSONと
  インメモリfloat結果を基準にする。
- RAW原本は永続保存していない。トリガ撮影の一時RAWは現像後に削除される。
