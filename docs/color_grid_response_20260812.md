## 1. 何を測ったか

生コード値駆動 321 色（6³=216 グリッド + R/G/B/グレー17段ランプ + RG/RB/GB 17段対角線）
と、gray-fit 逆LUT（`data/iso200_hdr_isoscan_d65_20260807/inverse_lut_gray`）を通した 35 色を、
固定シードのシャッフル順で投影し、LUT ROI の平均リニアRGBを 1 枚ずつ JSONL に記録した
（+ドリフト番兵 13 点）。撮影は `examples/python/measure_color_grid_response.py`、
解析は `examples/python/analyze_color_grid_response.py`（プロットと `analysis/summary.json` を生成、
何度でも再実行可）。r2 は 369/369 成功、平均 11.7 s/枚、約 72 分。

## 2. 主結果（r2）

### 2.1 線形化（ガンマ補正）は機能しているか

- **グレー軸はコード約180まで概ね線形化できている**（理想対角線との差 ~5%）。
  ただし**トップ端（要求 190〜235）で平坦化→240 で跳ぶ**構造が残り、
  max_dev は 0.22〜0.26、RMSE 0.079〜0.096（`analysis/lut_linearity.png` 左）。
  原因はプロジェクタ自身のグレー応答がネイティブコード 207 付近で不連続に跳ぶこと
  （§2.4）で、この跳びは 08-07 の計測でも同位置に再現しており、1D LUT では
  トップ端の逆変換が原理的に不安定になる。
- **単チャンネル駆動は gray-fit LUT では線形化できない**（同図右、軸別 max_dev
  R 0.30 / G 0.20 / B 0.08）。B は対角線の上、R は下と系統が割れる。
  これは LUT の欠陥ではなく次項の非加法性の帰結で、「単チャンネル LUT では
  不足」というこの実験の動機を実測で確認した形。

### 2.2 3チャンネル交差（非加法性・クロストーク）の実測

- **クロストークの主項は G駆動→R発光**: (0,255,0) で R=0.106（G自身 0.329 の 32%）。
  R駆動・B駆動はほぼ純粋（他チャンネル < 1%）。
- **加法性の破れは水準依存かつ非対称**（白 vs 原色和、Seime & Hardeberg 型）:

  | グレー水準 | R比 | G比 | B比 |
  | ---: | ---: | ---: | ---: |
  | 51 | **2.70** | 0.76 | 0.90 |
  | 102 | 1.64 | 0.97 | 0.73 |
  | 153 | 0.89 | 0.90 | 0.73 |
  | 204 | 1.07 | 1.01 | 0.83 |
  | 255 | 1.12 | 0.93 | 1.00 |

  暗いグレーで R が 2.7 倍の超加法、中間で B が 0.73 の劣加法。グリッド全体の
  混合色でも mix/sum 平均は R 1.25 / G 0.81 / B 0.80。既知の「最大1.7倍」
  （AGENTS.md §7.3）は水準を面的に見るとさらに広い範囲で割れている。

### 2.3 モデル比較 — 「1D線形化+行列」の残差は構造的

同じ 321 点への 10-fold 交差検証（ΔE76 は白正規化＋線形sRGB仮定の相対指標）:

| 順方向モデル | RMSE(線形) | ΔE平均 | ΔE p95 | ΔE最大 |
| --- | ---: | ---: | ---: | ---: |
| M1: ガンマ2.2 + 4×3行列 | 0.0291 | 13.35 | 36.3 | 54.1 |
| M2: channel_ramp LUT + 行列 | 0.0246 | 19.07 | 56.4 | 107.7 |
| M3: gray LUT + 行列 | 0.0277 | 15.17 | 40.8 | 57.0 |
| M5: 2次 root-polynomial | 0.0273 | 16.07 | 40.8 | 150.3 |
| **M4: TPS 3D散布補間** | **0.0148** | **3.33** | **10.2** | **17.8** |

- **現行モデル族（チャンネル毎1D線形化+行列）はどの線形化を選んでも ΔE平均 13〜19 が
  残り、フル3D写像（Grundhöfer & Iwai TIP2015 流の thin-plate-spline、scipy
  `RBFInterpolator` で実装）は 3.3 まで下がる**。約4倍の差が「1D+行列が原理的に
  取りこぼす量」の実測値。ADICT (ECCV 2010) が DLP で報告した「理想デバイスモデルで
  ΔE約2倍劣化」と同方向で、うちの機材ではそれ以上。
- 軸+グレーだけで fit して混合色を予測しても ΔE平均 11〜14 と全点 fit の CV と
  同水準 → 行列モデルの失敗は fit 点数の不足ではなく**構造的**（表現力の不足）。
- 交差項 √(g_i·g_j) を足した M5 が M3 からほぼ改善しないことから、非加法性は
  単純な2次交差項では書けない形をしている（グレー軸の不連続と水準依存の混合）。
- 自己整合性: LUT 通し 35 色の実測は、生グリッドから TPS で合成した予測と
  ΔE平均 1.62 / p95 4.5 で一致。計測と合成の筋は通っている。

### 2.3b 7ラインの入出力関係と比例性（2026-08-13 追加解析）

`plot_line_proportionality.py` → r2 `analysis/line_responses.png` /
`line_shapes.png` / `line_additivity.png`。R/G/B/RG/RB/GB/グレーの7ラインで
実測 vs 加法合成 vs ガンマ2.2形状を比較:

- **正規化形状は一致しない**（line_shapes）: 同じ出力chでもラインごとに形が
  割れ（中間〜明部で最大0.15）、どれも gamma2.2 より上に膨らむ。チャンネル毎
  1D LUT は「各パネルの曲線のうち1本」しか表現できない — 1D 系の誤差床が
  ライン分解で見える。
- **加法比は水準依存が激しい**（line_additivity）: RG/RGB ラインの c_R は
  暗部で **2.5倍** の超加法から始まり150以降ほぼ1へ収束。RB の c_B は暗部
  **0.4倍** の劣加法から1.3へ。GB の c_G は全域 0.8〜0.9 の劣加法。
  §2.2 の表（グレー水準のみ）の全ライン版。

### 2.3c 補助特性図（2026-08-15、可視化調査の推奨に基づき追加）

`plot_supplementary_figures.py` → r2 `analysis/chromaticity_tracking.png` /
`additivity_wyble.png` / `session_stability.png`:

- **色度トラッキング（カメラ基準、黒補正前後の対）**: R/B 原色は高駆動域で
  色度がほぼ一定（点が集束）だが、**G は黒補正しても軌跡が集束しない**
  （g成分 0.85→0.54）— G の色度シフトはフレア起因ではなく本質的
  （G→R クロストークの入力依存と整合）。測色較正ではないことに注意。
- **Wyble式加法性図**（差分第2軸つき重ね描き）: §2.2/§2.3b の加法性の破れを
  文献標準の形式で提示。c_R は中低域で正（超加法）→160付近で負転→207跳びで
  再度スパイク、c_B は中域で負（劣加法）。
- **セッション安定性**: 全5ランの番兵時系列。settle 0.3 s の r1 だけ ±4% で
  暴れ、settle 2 s の他ランは ±1% 内 — settle 延長の効果が run 横断で見える。

### 2.4 プロジェクタの動的挙動（測って分かったこと）

1. **コンテンツ適応の過渡（アイリス様）**: 切替 0.6 秒後の計測は直前パッチの明るさと
   相関 −0.73 で ±2〜4% ずれる（r1、settle 0.3 s）。settle 2.0 s にした r2 では
   番兵ドリフトが最大 0.9〜1.4% まで減少。定常状態は安定（グレー→赤ジャンプ後
   4〜49 秒で 0.396→0.403）。
2. **グレーのコード207付近の跳び**: ネイティブグレー応答が 204→224 で不連続に増える
   （R 0.40→0.57）。08-07 の計測と同位置・同形で再現し、投影順序に依らない
   （水準駆動の内部モード切替と推定）。
3. **G/B 単チャンネルのトップ端だけ順序依存**: 08-07 の昇順ランプは末端で跳ぶ
   （g223→g239: 0.24→0.37、b239→b255: 0.43→0.55）が、シャッフル順の r2 は滑らか
   （g255=0.329、b255=0.421）。R は両順序で一致（r255: 0.403 vs 0.408）。白も一致
   （1〜3%）。単色高輝度の連続表示が何かのブーストモードを踏む、という推定
   （推定であって切り分け済みではない）。

## 3. 副産物: HDRブラケットの飽和すり抜けバグ（発見・修正済み）

r1 の単チャンネル応答が「コード130で飽和し他chに漏れる」ように見えたのは
プロジェクタではなく**計測バグ**だった:

- 機構: 暗チャンネルを含む色（例 R255: G=B≈0.0004）は黒潰れ判定で +3 段の長露光
  ブラケットが走る。×4 以降 R はセンサ飽和するが、**現像値が 1.0 に張り付かず
  trust_high(0.96) を下回ってすり抜け**、÷露光比で採用されて R = 0.7/8 ≈ 0.087
  （真値 0.400 の 22%）。さらに飽和フレームから回収した暗チャンネルには現像色行列
  由来の偽クロストークが乗る（G: 真値 0.0005 → 0.030）。
- これは 2026-08-07 に `sample.py` で修正した「HDR白マゼンタ化」と同一クラスの残存で、
  `inverse_lut.capture_hdr_linear` / `_merge_hdr_exposures` に残っていた。08-07 の
  channel_ramp 校正が無事だったのは `channels=(c,)` ゲートが長露光自体を回避して
  いたため（偶然の回避であって防御ではない）。
- 証拠: 昇順逐次ランプの追試（`data/color_grid_response_20260812/sequential_ramp_probe.py`
  / 同 `.json`）が単一露光で 08-07 値を再現（r255: 0.4004 vs 0.4076）。
- 修正（`packages/core/yoshidacomp/compensation/inverse_lut.py`）:
  1. **マージの書き込み先を基準露光で判定**（sample.py の 08-07 修正と同方針）:
     信頼帯内は基準値、基準暗部のみ長露光から、基準飽和のみ短露光から回復。
  2. **予測飽和ガード**: 最明チャンネルが基準×スケールで trust_high を超えると
     予測される長露光は撮影自体を打ち切る（飽和チャンネルは現像色行列で同フレームの
     他チャンネルも汚染するため。triggered_batch 経路にも同ガードを追加）。
- テスト: 再現回帰テスト（旧実装に変異させると落ちることを確認済み）+ ガードの
  テストを追加。**全 462 件緑**（`tests/test_inverse_lut.py` 35 件を含む）。

## 4. 制約と読み方の注意

- 計測は **LUT ROI（右側の白面）の空間平均 1 点**。画素ごとの混色（行列の空間変動）は
  対象外。
- 条件は ISO200 HDR D65（ユーザー指定）。補償評価の最良条件 ISO400 非HDR とは
  異なるが、応答の「形」の診断が目的。グレー応答が 08-07 と一致することから
  日をまたぐ再現性はあるが、ISO400 への数値の外挿はしないこと。
- ΔE76 は「白正規化したカメラRGBを線形sRGBとみなす」相対指標。絶対測色ではない。
- 使用した gray LUT は 08-07 計測（5日前）のもの。トップ端の残差には経日変化も
  混じり得る。
- r1（`data/color_grid_response_20260812`）の鮮色・混合色の値は上記バグで汚染。
  グレー・暗部・番兵は有効。再解析には r2 を使うこと。

## 5. 含意と次の一手（提案）

1. **補償の上限は線形化の選択ではなく行列モデルの構造で決まっている。**
   リニア統一後の4方式の差が小さかった（ΔE 0.5 未満）のはこれで説明がつく。
   ΔE平均をさらに下げたければ、同じ 321 色データから作れる **3D 写像
   （TPS / 3D LUT）による補償**が次の一手（TIP2015 は逆写像を直接 TPS で組む。
   実装は `RBFInterpolator` + 今回の計測ループがそのまま使える）。
2. **グレー207跳びとG/Bトップ端の順序依存**はどのモデルでも危うい領域。
   プロジェクタ側の動的処理（ブーストモード/BrilliantColor 相当）を
   メニューで無効化できるなら、無効化してから全校正をやり直す価値がある。
3. 撮影を伴う全スクリプトの settle は 0.3 s では足りない（切替直後 ±2〜4%）。
   精度が要る計測は 2 s 以上を推奨。
4. `capture_hdr_linear` の修正は既存の校正フロー（build_inverse_lut 等）にも効く。
   HDR 有効の過去計測で「鮮やかな色 + 暗チャンネル」を含むものは同バグの影響を
   疑うこと（channel_ramp / gray の LUT 校正はゲートにより無事）。

## 7. 続報（同日）: TPS/3D写像補償の実装と実機評価

§2.3 の結論（1D+行列は構造的にΔE13〜19を残す）を受け、ノード格子TPS逆写像による
補償を実装し、同一校正データから fit した行列補償と実機で比較した。

### 7.1 実装

- `packages/core/yoshidacomp/compensation/block_tps_map.py` — 有効領域上の
  ノード格子（既定33×33）ごとに「カメラ色→プロジェクタコード」の逆写像を
  正則化TPS（`RBFInterpolator`、smoothing は LOOCV 自動選択）で fit し、
  適用時は周囲4ノードを双線形ブレンド。**入力は各ノードの実測色域ボックスへ
  クランプ**（`clamp_inputs=True` 既定、§7.3の理由）。
- `examples/python/capture_tps_calibration.py` — 6³=216色をシャッフル順・
  飽和ガード付きHDRで撮影→p2cワープ→1/4縮小してフレーム保存（再開可能）。
  実測 225ジョブ 約38分・エラー0（`data/tps_calibration_20260812`）。
- `examples/python/generate_tps_and_matrix_compensation.py` — 同一フレームから
  ①画素別アフィン行列（comp_no_gamma 相当）②ガンマ+行列（comp_gamma 相当）
  ③ノードTPS の3条件の補償画像を生成。
- `examples/python/evaluate_conditions_immediate.py` — 任意条件ディレクトリ群の
  実写評価（リニア統一採点、即時撮影経路）。

### 7.2 結果（5ターゲット平均、`data/tps_compensation_20260812/evaluation_r2`）

| 条件 | PSNR [dB] | SSIM | ΔE76 |
| --- | ---: | ---: | ---: |
| no_comp | 10.16 | 0.362 | 41.4 |
| 行列（アフィン） | 13.89 | 0.619 | 23.7 |
| ガンマ2.2+行列 | **14.17** | **0.653** | **21.9** |
| TPS（素） | 12.85 | 0.603 | 23.1 |
| TPS（クランプ） | 14.08 | 0.639 | 22.2 |

- **クランプ版TPSは最良の行列条件と同等（差は測定ノイズ内）**。彩度の低い
  ターゲットでは勝ち（car-new ΔE 14.7 vs 15.9、nature_2 18.0 vs 19.4）、
  彩度の高いものでは負けか同等。
- 素のTPSは明確に劣る: 観測色域の外の目標色で外挿がノードごとに違う方向へ
  暴れ、ブレンドすると補償画像に斑状のアーティファクトが出る（実画像で確認）。
  入力クランプで +1.2 dB 回復。

### 7.2b 追試: 行列 + TPS焼き込み3D LUT のハイブリッド

「1D逆LUTの席に3D LUTを置く」パイプライン同型のハイブリッド
（目標 → 画素別4×3行列（目標=基準応答の正規化色 c）→ TPS焼き込み33³格子の
三線形3D LUT）も同一校正から実装・評価した
（`compensation/color_lut3d.py` / `generate_hybrid_lut3d_compensation.py`、
`evaluation_hybrid`）。同一ランでの5ターゲット平均:

| 条件 | PSNR [dB] | SSIM | ΔE76 |
| --- | ---: | ---: | ---: |
| ガンマ2.2+行列 | **14.56** | **0.660** | **21.9** |
| TPS（クランプ） | 14.13 | 0.641 | 22.1 |
| 行列+3D LUT | 14.34 | 0.654 | 24.3 |

ハイブリッドは PSNR/SSIM で5枚中2枚最良（car 12.96dB、nature_1 13.20dB）だが、
**ΔE は全ターゲットで最劣**（平均 +2.4）。基準点（有効領域平均）の色バランスと
非線形形状を 3D LUT として全画素に焼き込むため、輝度・構造は改善する一方、
局所の色ずれを行列（アフィン）では戻し切れず系統的な色偏りが残る、と解釈できる。

### 7.2c 3D LUT の精度検証（2026-08-13 実機）

焼き込み3D LUT（`inverse_lut3d.npz`、33³）単体の精度を、要求色 c → LUT → 投影 →
実測 c の一致で検証した（73計測: グレー17 + 単ch15 + ランダム24 + held-out12 +
黒白アンカー + 番兵3、番兵ドリフト ≤1.5%）。
`validate_lut3d.py` / `analyze_lut3d_validation.py` /
`data/lut3d_validation_20260813/`。

| セット | n | 達成色 rmse (c単位) | ΔE76平均 |
| --- | ---: | ---: | ---: |
| グレー軸 | 17 | 0.063 | **4.2** |
| held-out（校正実測色=確実に到達可能） | 12 | 0.080 | **4.5** |
| ランダム（LUT定義域 [0,1]³ 内） | 14 | 0.077 | **5.8** |
| ランダム（c>1 の域外要求） | 10 | 0.130 | 11.9 |
| 単ch（c=0 成分は到達殻の外） | 15 | 0.085 | 9.5 |

誤差の内訳（切り分け済み）:

1. **到達可能・定義域内なら ΔE ≈ 4〜6** — オフラインCV予測（達成c rmse 0.041）と
   同オーダー。1D gray LUT（§2.1: グレー軸 rmse 0.079〜0.096、混合色は原理的に不可）
   に対し、グレーで改善しつつ**混合色まで同精度で扱える**のが3D LUTの利得。
2. **グレー中間域に +0.011〜0.028 の系統バイアス** — 白アンカーは前日比 ±1.5% で
   一致しており正規化ずれではない。応答形状の日スケール漂移（中間域数%）が原因。
   グレー軸限定のバイアスで、held-out へ外挿すると悪化する（大域補正は不可）。
3. **要求 c≈0.75〜0.95 のグレーで +0.09〜0.11 のオーバーシュート** — プロジェクタ
   自身の 207 跳び（§2.4）による逆写像の畳み込み。静的な逆写像では原理的に
   解消できない（デバイス側の不連続）。
4. 域外要求（c>1 や単chの c=0 成分）は LUT の [0,1]³ クランプ／到達殻で頭打ち —
   これは色域誤差であって LUT の誤差ではない。
5. 焼き込み（TPS→33³三線形）の乖離は平均 0.014。軸平行ボックス内でも到達殻の外の
   未使用領域では最大 0.52 まで開く（両者とも外挿する領域の差。実用域では小さい）。

**結論: 3D LUT は「到達可能な色を要求する限り」基準点で ΔE 4〜6 の精度で色を
再現する。** 残差の主因は (a) プロジェクタの日スケール漂移と 207 跳び（デバイス
起因）、(b) 色域外要求（ターゲット側の問題）で、LUT 自体の写像誤差は二次的。

**区分線形3D LUTとの実機ペア比較**（2026-08-13、`bake_inverse_lut3d_linear()`
= 実測216点の Delaunay 重心座標補間で焼いたLUT。同一シード・同一要求色68点を
連続2ランで検証。`data/lut3d_validation_20260813_linear/`、ペア散布は
`analysis/lut3d_tps_vs_linear_paired.png`）:

| セット | TPS ΔE | 線形 ΔE | ペア差(線形−TPS) |
| --- | ---: | ---: | ---: |
| グレー軸 | 4.16 | **2.25** | −1.92（線形が14/17勝） |
| 単ch（殻外） | **9.46** | 13.53 | +4.06 |
| ランダム | **8.37** | 9.69 | +1.33 |
| held-out | **4.55** | 6.42 | +1.88（線形は1/12勝のみ） |
| 全体 | **6.88** | 8.10 | +1.22 |

- **グレー軸は線形が明確に勝つ（2.25）** — TPS版のグレー中間バイアス
  +0.011〜0.028 の相当部分は日漂移ではなく **TPS平滑化（λ=1e-4）のバイアス**
  だったと判明（線形は標本を厳密に通るため消える）。§7.2c の解釈を一部訂正。
- **held-out で線形が1/12しか勝てない**のは示唆的: 標本を厳密に通る補間は
  校正1回分の計測ノイズ（アイリス±1〜2%）まで再現する＝過学習。平滑化TPSの
  方が翌日の再計測に対して汎化する。3D の bulk と殻近傍も TPS 優位。
- 含意: 校正を多パス平均でノイズ低減すれば線形（厳密補間）が全域で
  有利になる可能性が高い。現状の1パス校正では **TPS(λ=1e-4) が総合最良、
  グレー軸だけは線形が最良**。

### 7.3 解釈 — 律速は色モデルではなく色域

到達可能な色に限れば TPS の優位は大きい（§2.3 と同じデータでの逆写像
シミュレーション: 216色fit で達成色ΔE 4.3 vs 行列 21.6）。しかし実ターゲットは
ノード観測域の外の色を大量に要求しており（ノード×ターゲットの49%が観測
ボックス外）、そこではどのモデルも同じ色域の壁に当たる。**全画像平均の指標は
色域外画素に支配され、色モデルの差はかき消される。** これは既知の
「色域外46.5〜85%」「白応答不足が上限を規定」（AGENTS.md §9、
gamut-clipping 調査）と整合する。

TIP2015 が補償写像とセットでクリッピング誤差の大域最適化（目標をなめらかに
色域内へ落とす前処理）を持っているのはこのためで、**TPSの利得を実画像で
引き出すには目標の色域マッピングが前提**になる。

### 7.4 次の一手

1. **目標の色域マッピング**（全体スケールダウン、または TIP2015 型の
   勾配保存最適化）を入れてから行列 vs TPS を再比較する。色域内に収めた
   ターゲットでは点計測で4〜5倍の差が確認済み。
2. プロジェクタの動的処理の無効化検討（§5）— 色域と非加法性の両方が緩む
   可能性がある。
3. 撮影経路の絶対スケール不整合（§7.5）の根本原因調査。
